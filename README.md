# jaegosilsa

POS 엑셀의 제품 정보를 정리하고 바코드 스캔으로 실물 수량을 집계하여, 현매장 재고와의 부족·초과를 확인하는 재고실사 사이트입니다.

## 목표

각자의 PC 브라우저에서 로그인 없이 실사하고, 원본 음수·양수 재고와 실사 차이를 구분하여 결과를 엑셀로 내려받습니다.

## 수락 기준

- [x] 고정 POS XLSX의 상품명·옵션명·바코드 번호·현매장 재고를 읽고 문자열 바코드와 부호 있는 수량을 보존한다.
- [x] 일반 상품은 품번·색상을 분리하고, 예외 상품과 옵션명 원문은 확인 표시와 함께 보존한다.
- [x] 스캔당 1개 누적하고 잘못 찍은 수량을 취소·수정한다.
- [x] 실물 − 기준 재고 차이와 원본 재고 부호를 따로 표시한다.
- [x] 미등록 바코드는 집계하지 않고 화면 경고 및 한국어 “오류” 발화 요청·오류 상태를 처리한다.
- [x] 새로고침 후 각자의 실사를 복원하고 화면과 일치하는 XLSX 결과를 내려받는다.
- [x] 사용자가 현재 환경에서 음성 재생을 확인했습니다.
- [x] 정상 스캔의 수량 저장 성공 뒤에만 짧은 비프음으로 등록 완료를 알립니다.
- 물리 스캐너 시험은 장비 미보유로 이번 수락 범위에서 제외했습니다. 입력 지원 기능은 유지하지만 실제 장비 호환성은 미검증입니다.

전체 수락 기준은 [정식 명세](docs/harness/seed.yaml)의 `acceptance_criteria`에 있으며, 확인 근거는 [검증 보고서](docs/harness/verification-report.md)에 있습니다.

## 제약

- 기준은 `현매장 재고` 한 열이며 창고·다른 매장 수량을 합산하지 않습니다.
- 파일과 실사 데이터는 브라우저에서 처리·저장하고 서버로 전송하지 않습니다.
- 로그인·공동 실사·PC 간 동기화·휴대폰 카메라·외부 사이트 자동 수정은 제외합니다.
- 브라우저 데이터를 지우면 실사 기록도 지워집니다. 음성 재생은 사용자 확인 완료이며 다른 환경의 오디오 정책은 별도입니다.

## 상태

로컬 앱이 구현되어 실행 가능합니다. 검증 근거는 [검증 보고서](docs/harness/verification-report.md)에 있습니다. 사용자 음성 재생 확인을 반영했고 물리 스캐너 시험만 이번 범위에서 제외했으며, 스캐너 호환성을 검증했다고 주장하지 않습니다.

## 실행

Node.js 24 이상과 최신 Chrome/Edge를 사용하세요. 한국어 음성이 설치되어 있어야 합니다. 브라우저의 **음성 테스트**로 먼저 소리를 확인하세요.

```sh
npm install
npm run dev
```

`http://127.0.0.1:5173`을 열고 POS `.xlsx`를 선택한 뒤 스캔 입력란에 바코드를 입력합니다. Enter 또는 Tab으로 등록하며 한 번에 1개를 집계합니다.

```sh
npm test
npm run build
npm run preview
```

프로덕션 결과는 `dist/`이며 preview 주소는 `http://127.0.0.1:4173`입니다. 브라우저 저장은 origin별로 분리되므로 개발·preview·배포 주소 또는 `localhost`와 `127.0.0.1` 사이에 기록이 자동 이동하지 않습니다.

## Vercel 배포

실제 사이트는 **[https://jaegosilsa.vercel.app](https://jaegosilsa.vercel.app)** 입니다. 프로덕션 배포가 READY 상태이며, 로그인하지 않은 HTTP 요청과 실제 브라우저에서 접근·파일 가져오기·스캔·복원·결과 다운로드를 확인했습니다.

사용자가 비업무용 개인 프로젝트임을 확인하여 `marahmiks-projects/jaegosilsa`를 Hobby 플랜으로 배포했습니다. 유료 전환이나 구매는 수행하지 않았습니다. 향후 상업·업무 용도로 바뀌면 [Hobby의 비상업적 개인 용도 제한](https://vercel.com/docs/plans/hobby)을 다시 확인해야 합니다.

`app-ci`는 `main` push와 pull request에서 Node.js 24로 `npm ci`, `npm test`, `npm run build`를 실행하며 배포하지 않습니다. Vercel 프로젝트의 Git 연결은 해제했고 `vercel.json`의 `git.deploymentEnabled: false`도 유지합니다. **Git push만으로 사이트가 갱신되지 않으며 승인된 수동 재배포가 필요합니다.**

전체 리셋 기능은 현재 로컬 구현·검증 상태이며 위 공개 사이트에는 아직 재배포하지 않았습니다.

### 수동 재배포

1. Vercel CLI로 인증하고 이미 연결된 `marahmiks-projects/jaegosilsa` 프로젝트를 사용합니다. `.vercel`과 `.env*`는 로컬 설정·인증 관련 파일이므로 커밋하지 않습니다.
2. 프로젝트 루트는 `.`이며 Framework Preset은 **Vite**, Install Command는 `npm ci`, Build Command는 `npm run build`, Output Directory는 `dist`, Node.js Version은 **24.x**입니다.
3. 설치·테스트·빌드를 성공시킨 뒤 [로컬 production 빌드](https://vercel.com/docs/cli/build)의 `.vercel/output`을 [prebuilt production 배포](https://vercel.com/docs/cli/deploy#prebuilt)합니다. 이번 배포에는 CLI `63.1.2`의 `vercel build --prod --yes --scope marahmiks-projects` 및 `vercel deploy --prebuilt --prod --yes --scope marahmiks-projects`를 사용했습니다. 원본 XLSX·저장소 내부 문서는 배포물에 포함하지 않습니다.
4. Windows에서 preview나 TypeScript 언어 서버가 네이티브 파일을 잠그면 `npm ci`가 EPERM으로 실패할 수 있습니다. 에디터 프로세스를 강제 종료하지 않고 동일 소스와 프로젝트 연결 설정을 복사한 별도 임시 폴더에서 설치·빌드하는 방식으로 이번 배포를 검증했습니다.
5. 공개 확인은 위의 안정적인 production 주소에서 로그인 없이 진행합니다. Vercel의 기본 보호 설정은 유지하므로 개별 deployment URL은 로그인을 요구할 수 있습니다. 소스 공개용 `--public` 옵션은 사용하지 않습니다. 이 앱에는 서버 데이터 저장이나 제품 파일 업로드용 환경 변수가 필요하지 않습니다.

정적 앱만 배포하며 함수나 전체 경로 SPA rewrite는 사용하지 않습니다. 클라이언트 라우트가 없으므로 worker와 정적 파일은 실제 파일 경로로 제공해야 합니다. POS 파일·제품·실사 기록은 브라우저에서 처리·저장하며 서버로 업로드하지 않습니다.

### 사용 전 체크리스트

- 승인된 배포 주소에서 XLSX 가져오기 worker가 실제로 로드되고, POS 파일 가져오기와 결과 XLSX 다운로드가 작동하는지 확인하세요.
- 등록 바코드의 저장 완료 뒤 비프음이 한 번 실제로 들리는지 확인하세요. 미등록 바코드는 수량을 바꾸지 않고 화면 경고와 한국어 “오류” 음성 또는 음성 오류 상태를 표시해야 합니다. 현재 환경의 기존 음성 확인을 새 배포 환경의 비프음 청취 확인으로 대체하지 마세요.
- 새로고침 후 복원과 저장·오디오 실패 안내를 확인하세요. 물리 스캐너 실기 시험은 장비 미보유에 따른 사용자 승인으로 이번 수락 범위에서 제외했으며, 실제 스캐너 호환성은 미검증임을 유지하세요.
- 안정적인 production URL을 정한 뒤 실사를 시작하세요. preview URL·도메인·프로토콜·포트가 바뀌면 origin별 기록이 자동 이동하지 않습니다. 주소 변경이나 브라우저 데이터 삭제 **전에 결과 XLSX를 내보내세요**. 내보내기는 결과 보관용이며 다른 origin으로 실사 상태를 자동 복원하지 않습니다.


## 사용 시 주의

- 파일 교체는 확인 후 실물 수량을 0으로 초기화합니다. 신제품은 실사 시작 전에 최신 POS 엑셀로 반영하세요.
- 다운로드 왼쪽의 **전체 리셋**은 확인 후 이 브라우저의 불러온 파일 정보·제품 목록·스캔/수정 수량을 모두 삭제합니다. 새로고침해도 복원되지 않으므로 필요한 결과는 먼저 다운로드하세요. PC 원본 엑셀은 삭제하지 않으며 취소·삭제 실패는 기존 기록을 유지합니다.
- 수량 수정은 해당 제품의 과거 스캔 취소 이력을 지웁니다. 새로고침 후 취소 이력은 복원하지 않습니다.
- 결과 다운로드는 현재 검색·필터와 관계없이 전체 제품을 포함합니다.
- 저장 실패나 음성 미지원은 화면에 표시됩니다. 저장 오류를 해결하기 전에는 저장 완료로 간주하지 마세요.
- 입력 한도는 XLSX 16 MiB, 제품 100,000행, 128열, 범위 8,000,000셀입니다. 초과 파일은 잘라서 가져오지 않고 거절합니다. 이 한도는 ZIP 압축 해제 메모리 안전성을 보장하는 것은 아닙니다.
- 같은 브라우저의 여러 탭에서 같은 실사를 동시에 집계하는 방식은 지원 범위가 아닙니다.
- 정상 스캔 성공음은 짧은 비프음이며 미등록·저장 실패·수정·취소에는 울리지 않습니다. 브라우저 오디오가 차단되면 성공음 상태에 안내하고 저장된 집계는 유지합니다. 기존 “오류” 음성은 별도로 유지합니다.
