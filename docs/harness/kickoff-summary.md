- 현재 수동·브라우저 검증 범위는 실제 샘플과 키보드형 Enter/Tab 입력의 반복 등록·취소·수정·부호 확인·저장/복원·다운로드입니다. 음성 청취는 사용자 확인으로 수락했으며 물리 스캐너 실기 시험은 사용자 승인으로 이번 범위에서 제외합니다. 최초 킥오프에는 PC 스캐너 실기 시험을 계획했지만 그 계획은 개정되었습니다.
- 승인된 자동 검증: 부호 계산, 바코드 문자열 보존, 미등록/충돌·오류 입력의 기록 보존, 결과 파일 일치를 결정적 데이터로 확인한다.
- 최초 킥오프 당시에는 앱 명령이 없었습니다. 현재 실제 명령은 package.json의 npm test, npm run build, npm run preview이며 실행 근거는 verification-report.md에 있습니다. 확인된 사용자 음성 관찰이나 하네스 실패를 재실행해 추측하지 않습니다.

## Out of Scope
- 로그인·계정 및 서버 데이터 저장
- 다른 PC·브라우저 간 동기화 및 여러 사람의 공동 실사
- 휴대폰 카메라 스캔
- 외부 사이트 재고 자동 수정 또는 외부 사이트 업로드 전용 양식
- 다른 사이트 엑셀 양식 및 XLS·CSV 파일 지원
- 미등록 바코드 별도 제품 집계 및 품번·색상 추측 생성
- 물리 스캐너 실기 테스트는 장비 미보유에 따른 사용자 승인으로 이번 작업에서 제외합니다. 입력 지원 기능은 유지하며 실제 장비 호환성을 검증했다고 주장하지 않습니다.

## Assumptions
- 사용자가 고정 양식이라고 확인한 POS XLSX의 Sheet1과 헤더 구조가 다음 다운로드에도 유지된다.
- 실물 PC 스캐너는 키보드형이며 Excel 바코드 값을 입력한다고 전제합니다. 사용자가 장비 미보유로 이번 실기 테스트 생략을 승인했으며 실제 장비 호환성은 미검증입니다.
- 최초 킥오프에는 앱 스택과 명령이 미정이었습니다. 현재 정적 앱은 Vite·TypeScript로 구현되어 있고 실제 패키지·실행·검증 명령은 package.json과 verification-report.md에 기록되어 있습니다.

## Risks
- 브라우저 저장소 삭제·용량 제한·저장 실패 및 다른 origin에서의 기록 격리. 저장 실패는 사용자에게 표시하고 저장됐다고 허위 보고하지 않는다.
- 62,080개 제품을 다루므로 가져오기·표 표시·수량 갱신·저장에서 메인 스레드 정체와 데이터 손실을 점검해야 한다.
- 물리 스캐너의 실제 바코드 값과 Enter/Tab 종료 신호는 검증하지 않았습니다. 테스트 제외는 사용자 승인에 따른 이번 범위 결정이며 장비 확보 후 별도 확인이 필요합니다.
- 사용자가 현재 환경의 음성 재생을 확인했습니다. 다른 PC·브라우저의 음성 가용성이나 오디오 정책까지 보장하지 않습니다.
- 샘플 바코드는 모두 문자열이지만 다른 파일의 숫자 셀에서 이미 유실된 앞자리 0은 복원 근거 없이 추측할 수 없다.
- 음수 기준 수량은 실물 0에서도 양수 차이를 만든다. 원본 재고 부호와 실사 차이 부호를 혼동하지 않아야 한다.
- 원본 POS 데이터와 브라우저 입력은 신뢰하지 않는다. 상품명 출력과 XLSX 내보내기에서 HTML 실행·수식으로의 해석을 피한다.
- 하네스 2026.87 Windows 검사에서 29건 실패했고 FIFO probe로 테스트 파일 3개가 초기화 중단됐습니다. upstream #98에 보고했으며 앱 검증과 구분합니다.
