- 키보드형 Enter/Tab 입력 자동 검증은 유지합니다. 사용자가 스캐너 미보유로 이번 물리 장비 시험 없이 진행하도록 승인했으므로 실기 확인은 이번 범위에서 제외합니다. 물리 스캐너 호환성이 검증됐다는 뜻은 아닙니다.

- 음성 미지원/차단/실패는 화면으로 명확히 알립니다. 음성 대신 화면만 표시하고 정상 동작이라고 보고하는 가짜 대체는 만들지 않습니다.

## 독립 test-attack 보완

계획 검토 PASS이며 CRITICAL 지적은 없었습니다. 다음 사항은 기존 AC의 검증을 구체화합니다.

- 저장 전환: A 스캔 → 수량 0 수정 → 스캔 → 취소 및 A/B 교차 입력 후 마지막 완료 상태를 재로딩합니다. 파일 교체와 이전 저장이 겹치지 않게 직렬화합니다.
- 취소: 최근 성공한 스캔을 대상으로 하며 미등록/실패 스캔은 취소 목록에 넣지 않습니다. 수동 수량 수정 시 해당 바코드의 이전 취소 이력은 제거합니다. 이력 소진은 수량을 바꾸지 않습니다. 새로고침 후 취소 이력 보관은 요구하지 않습니다.
- 파일 원자성: 유효한 앞 행 다음의 잘못된 마지막 행 또는 멀리 떨어진 중복 바코드도 파일 전체를 거절합니다. 교체 취소/실패 시 이전 제품·수량·파일 정보가 즉시 및 재로딩 후 유지됩니다.
- Worker: 동시에 여러 가져오기/내보내기를 실행하지 않습니다. 실패/취소 시 busy를 해제하고 이전 상태를 보존합니다. Worker 메시지·실행 오류와 다음 정상 작업을 검증합니다.
- 입력: Enter/Tab 한 번에 정확히 1개, 입력 초기화와 스캔 포커스 유지, 연속 종료 신호·키 반복·수량 수정 입력과 스캔 입력의 분리를 확인합니다.
- 행 보존: 결정적 워크북의 모든 바코드별 레코드를 비교합니다. 실제 샘플의 마지막 행·0재고·예외 상품을 검색/스캔/결과에서도 확인합니다.
- 내보내기: 저장 대기열을 완료한 시점의 스냅샷으로 생성하며 생성 중 집계/파일 교체를 막습니다. 필터/현재 페이지와 관계없이 전체 제품을 내보냅니다.
- 부호: 양수 기준의 부족/일치/초과, 0 기준의 일치/초과, 음수 기준의 초과를 서로 다른 필터에서 정확히 분류합니다.
- 숫자: 빈 문자열·공백·불리언·수식/오류 셀을 0으로 변환하지 않습니다. 개별 값·차이·전체 합계의 안전 정수 범위를 넘으면 상태를 바꾸지 않고 명시적 오류로 처리합니다.
- 복원: 제품 필드·음수 기준·선택 파일 정보·집계를 함께 복원합니다. 삭제/빈 저장소는 실사 없음으로 표시하고 다른 origin과 격리합니다.
- 보안: 상품명뿐 아니라 옵션·바코드·파일명·헤더/오류 문자열도 실제 DOM에서 텍스트로만 출력되는지 확인합니다. XLSX 문자열은 수식으로 저장하지 않습니다.

## 정상 스캔 성공음 — AC10

- 정상 바코드를 Enter/Tab 또는 등록 버튼으로 입력하여 저장 완료한 경우 짧은 비프음의 실제 Web Audio 신호가 한 번 생성되는지 확인합니다. 기존 버전에서 신호가 없다는 RED를 먼저 관측합니다.
- 같은 바코드를 연속 등록해 각 성공한 집계에 한 번씩만 신호가 발생하는지 확인합니다. Enter 후 빈 Tab이나 키 반복으로 추가 음향·집계가 생기지 않아야 합니다.
- 미등록·빈 입력·실패한 저장에는 성공 비프음이 없어야 합니다. 미등록의 기존 오류 음성 구현은 유지하며 사용자의 기존 음성 청취 확인을 재검증하지 않습니다.
- 수량 수정과 스캔 취소에는 성공음을 내지 않습니다.
- 실제 IndexedDB 트랜잭션을 보류했다가 완료/취소하여 저장 완료 이전이나 취소 후에 성공음이 나오지 않는지 확인합니다.
- 오디오 미지원 또는 resume 실패를 일회성 브라우저 진단으로 유도해 재고 저장·집계는 유지하고 성공음 상태 오류를 표시하는지 확인합니다.
- 자동화는 네이티브 AudioContext·AnalyserNode에서 생성된 신호를 관측합니다. 사람의 스피커 청취나 물리 스캐너 호환성을 증명했다고 기록하지 않습니다. 영구적인 음향 mock·호출 전달 테스트는 만들지 않습니다.
- 기존 앱 회귀 테스트와 프로덕션 빌드를 실행합니다. 하네스의 알려진 실패나 사용자 확인이 끝난 오류 음성을 재실행하지 않습니다.
- 오디오 준비 타임아웃 뒤 실제 context가 running으로 회복된 후 지연 저장이 성공하는 경계도 확인합니다. 과거 준비 실패 값만으로 재생을 영구 차단하지 않아야 합니다. 이 짧은 신호의 관측에는 렌더러 프레임 샘플링 누락을 피하려고 일회성 네이티브 AudioWorklet의 오디오 스레드 신호를 사용합니다.
